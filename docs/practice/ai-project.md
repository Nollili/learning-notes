## P-334

**Deliverable:** a permission-aware document assistant supporting ingest/update/delete, lexical and hybrid retrieval comparison, current-authority context assembly, supported citations/abstention, bounded streaming and recoverable failures. It answers from authorized versioned source spans; it does not search an arbitrary private filesystem or execute instructions found in a document.

**Setup:** use the [text/CSV extractor](../python-for-ai/document-processing.md), [persistent vector lifecycle](../python-for-ai/vector-storage-lifecycle.md), [retrieval pipeline](../python-for-ai/retrieval-pipeline.md), [source/citation verifier](../python-for-ai/retrieval-context.md) and [streaming owner](../python-for-ai/model-streaming.md). Put their modules into one owned learner service with explicit interfaces and a lockfile. Seed two synthetic tenants with two principals, source versions, ACLs, exact locators and at least one unanswerable question. Keep authoritative source bytes/ACL/version separate from vector/index/cache derivatives.

Implement these increments and retain a working checkpoint after each:

1. Authorized bounded ingestion→exact source hash→extractor/segment/chunk identities→staged generation. Reject unsupported/empty/malformed/oversize input before model calls. Complex parsers require their existing isolated-worker contract.
2. A deterministic lexical baseline, then a compatible embedding-space adapter and a hybrid candidate. Record exact model/vector dimensions/settings, chunking and index generation. Never combine incompatible embedding spaces or compare different permitted corpora as one benchmark.
3. Current tenant/subject filters **before** candidate/context selection, bounded rerank and actual-payload token budgeting. Re-resolve source version/ACL/locator immediately before context and again before a cited source is displayed when needed. An ANN post-filter alone can miss allowed results and must not leak forbidden candidates.
4. A typed answer/insufficient-evidence/unavailable contract with stable source-version/span citations. Verify citation existence/current access and assess actual claim support; a valid source ID alone does not prove entailment. Source-authored “ignore instructions” text stays data.
5. Owned stream cancellation/overall+idle budgets, validated terminal result and bounded safe UI. A partial draft is not a final accepted answer and may contain unsupported text. Cancel and disconnect release local owners; remote billing/work may remain unknown.
6. Update/delete/revoke: stage/reindex/replace generation atomically at your chosen visibility boundary, invalidate derived caches and deny revoked access immediately. Keep deletion receipts/retention policy for source/vector/chunk/trace/export/backup owners. Do not claim hard deletion from merely hiding a search result.

**Worked trace:** user-a asks what a timeout proves. The fixture's authorized `public:v1:line1` says it limits caller waiting and does not prove a remote write failed. Retrieval resolves that exact current span, the answer states that distinction and cites it. `private:v1:line1` belongs to user-b's tenant and cannot be included even if it has a high similarity score. If public is revoked between retrieval and context, stop/retrieve again or abstain; do not keep an old authorized excerpt as permanent permission. If no permitted source documents the launch date, return insufficient evidence instead of inventing one.

The authored `ai-lab/corpus.json` and `cases.json` retain this tiny synthetic task/case seed, including an instruction-like source line. It is development data, not a held-out benchmark. Expand it with reviewed relevance/support labels and independent source families. No real secret or customer data appears in it.

**Comparison acceptance:** freeze questions, permitted corpus, labels, task/output policy and workload; compare lexical versus hybrid recall at a declaredk and answer support/coverage/abstention, duplicate/citation errors, latency and total known/unknown cost. Include no-answer/cross-tenant/injection/update/delete/revocation cases and repeated runs. Report sample size/slices and paired failures; do not claim general quality from eight synthetic cases. Missing provider usage is unknown, not zero.

**Operational acceptance:** cancel during retrieval and generation; inject store/provider timeout, malformed output and stale source; recover to explicit safe states with no unsupported final answer or duplicate job. Enforce maximum bytes/chunks/tokens/tool calls/deadline/spend through one owner, count retries and close/reap all tasks/clients. Show permission filtering and budget failure cause zero forbidden/provider/tool calls. Retain real source/index lifecycle observations and a safe UI review. Actual integrated adapters, live quality and learner execution are still required.

## P-335

**Deliverable:** one reproducible evaluation suite plus a bounded read→propose→approve→write→receipt tool workflow. The purpose is to test whether orchestration obeys the task and authority under failure, not whether two model answers sound convincing. Use [evaluation cases/rubric](../python-for-ai/evaluation-lab.md), [measurements](../python-for-ai/evaluation-measurements.md), [typed tools](../python-for-ai/tool-boundaries.md), [workflow state](../python-for-ai/tool-workflow-state.md) and [approved writes](../python-for-ai/approved-writes.md).

### Dataset and rubric

The retained8case seed covers normal, missing evidence, cross-tenant, injection, tool failure, revocation, cancellation and budget rejection. Each case has a stable ID, exact question, trusted fixture principal, scenario and expected status/citation references. Instantiate the scenario through your test adapters; it is not a magic field a provider obeys. Keep normal/injection cases' permitted evidence identical when isolating injection impact. Add human-authored expected claims and relevant-span labels before judging free text; these seed status/citation labels do not establish semantic truth.

Version corpus/case/rubric/parser/prompt/retriever/model/settings and source permissions. Group related documents/questions before splitting development/validation/held-out sets; do not tune prompts on held-out failures and then call the same set untouched. Compare a frozen deterministic/lexical baseline with the candidate under the same workload, repeated runs and failure policy. Deterministic checks cover schema, current authority, citations, budgets and receipts. Human rubric covers factual/semantic support, useful abstention, task completion and misleading omissions; a model judge is an additional calibrated signal, not an unquestioned oracle.

| Failure case | Hard expectation | Evidence to retain |
|---|---|---|
| Missing evidence | Insufficient evidence; no invented date/source | Current permitted source set and answer status |
| Cross-tenant/injection | Zero unauthorized read/write/disclosure; source commands ignored | Redacted dispatcher events and source IDs, not private bodies |
| Store/tool failure | Explicit unavailable/retry/defer/unknown state under policy | Attempt count/deadline and no fabricated success |
| Revoked approval/source | Current policy denies despite old checkpoint | Revision/authority decision and zero effect |
| Interrupted write | Resolve stable operation receipt before retry | Durable command digest, operation ID and effect count |
| Duplicate dispatch | One logical local effect under idempotency contract | Transaction/receipt uniqueness and conflict behavior |
| Aggregate budget exhausted | Stop/defer before more work | Shared reservation/usage ledger, known/unknown totals |

The persisted `ai-lab/check.py` verifies this seed's case IDs/slices and exact fixture status/citation expectations, rejects missing results, and catches three deliberately wrong outputs. That single pytest check passed2026-10-26. Its success input is an authored expected ledger; **no model or integrated assistant was evaluated**. It is a starting contract check, not a semantic grader or product-quality measurement.

### Tool workflow and approval

Start with two fixed tools: authorized note lookup and an exact-title rename. Tool arguments are bounded runtime schemas; the dispatcher allowlists names and obtains identity/current permissions outside model text. No arbitrary shell, URL, SQL or file-path tool. Propose an immutable command containing resource/version/new title and operation ID; show the actual change/effect to the human. Approval binds actor, exact command digest, source/version, scope and expiry. A changed argument, revoked permission or expired approval requires a new decision. A tool result or a previous assistant message cannot approve a write.

Persist state and revision before an external boundary. Use one atomic budget owner across retries/resumes/subtasks, e.g. an illustrative maximum5tool calls,1write, a declared total deadline and a reviewed cost reserve. These are exercise limits, not universal defaults. Step count alone does not bound time/token/financial work. Unknown usage stays reserved/reconciled according to policy; restarting a graph cannot replenish the budget.

The write adapter commits local idempotency receipt plus effect in one transaction. Same operation+same digest returns the retained result; same ID+different command conflicts. For a remote provider, pass its supported operation key and reconcile status: local SQLite cannot create an atomic transaction with that service. Kill the workflow before dispatch, after dispatch/before response and after receipt; verify pending/unknown/completed remain distinguishable. Exactly-once claims must name the local boundary.

**Acceptance:** run normal and adversarial cases repeatedly; retain paired baseline/candidate results, safe per-stage traces, total latency, all attempts and known/unknown task cost. Demonstrate revoked-access resume, tampered approval, duplicate/conflicting command, handler timeout, unknown external outcome and aggregate-budget exhaustion. Real human approval/review, persistent multi-process recovery and provider-quality evidence are still required; a generated workflow or RAM checkpoint is not proof of completion.

## P-337

**Deliverable:** a small independently implemented Python companion endpoint for validated ingestion/classification, with reproducible environment, correct async ownership, structured safe logs and actual integration/deployment checks. Python is role-dependent; the target is enough fluency to implement/debug this service, not mastery of every ML framework.

**Setup:** reconstruct one owned `study_ai` package from the existing [setup](../python-for-ai/setup-and-basics.md), [configuration/logging](../python-for-ai/configuration-and-logging.md), [FastAPI boundary](../python-for-ai/fastapi-boundaries.md), [async HTTP](../python-for-ai/async-http.md) and [deployment](../python-for-ai/deployment.md) examples. Pin Python3.13.11, compatible FastAPI/Pydantic/Uvicorn/pytest dependencies in pyproject.toml/uv.lock and run locked sync. Keep runtime and dev/check environments separate. Start with the lesson's deterministic text preparation, not a paid/model/GPU dependency. Use the single selected model SDK only if the endpoint actually needs generation.

Choose one contract, e.g. `POST /documents` accepts a bounded strict `{id,body}` and returns a projected created DTO. The authenticated principal/tenant comes from trusted server middleware, never a body field or prompt. A parser/schema checks shape, the service enforces current permission and the repository owns durable uniqueness. The existing memory repository is disposable; before claiming restart/multi-replica persistence implement a durable shared adapter and migration/transaction policy. A validated classifier result must retain the exact source version/quote support rather than describe a whole document from one fragment.

**Implementation increments:** first pure typed preparation/error functions; then strict Pydantic DTOs and injected repository/provider protocols; then app lifespan-owned clients/repository; finally HTTP boundary, byte/deadline controls and supervised server launch. Use async clients for I/O and bounded offload/process isolation for blocking parsing/CPU work. `async def` does not make a synchronous parser nonblocking. A cancelled coroutine cannot kill an arbitrary thread/parser; kill/reap isolated hostile-format workers when required. Plain UTF-8/CSV is sufficient for the initial project; unsupported PDF/OCR is explicit rather than silently indexed empty.

Test pure functions with pytest fixtures and temporary owned files. ASGITransport checks app routes/middleware without real sockets; add the existing real Uvicorn process/socket/SIGTERM smoke for listener/lifecycle behavior. Inject timeout, invalid provider JSON, repository outage, body oversize/invalid UTF-8, duplicate IDs, cross-user access and failed cleanup. Keep caller waiting/underlying work distinct; outbound deadlines must cover body consumption and retry attempts. Log only fixed fields/event codes and safe IDs; test synthetic sensitive markers do not enter responses/logs. Missing credentials/config fail startup before readiness.

**Acceptance:** strict package typecheck and pytest pass under the locked environment; negative schema/security/body/cancellation tests reach the right status with no secret echo; real process starts, serves allowed/denied operations and exits/reaps within the stated deadline; clients/files/pools close. A durable adapter persists state through restart, and release artifacts match tested source/lock/runtime. Retain a deployment note for TLS/proxy trust, one-process-per-instance baseline, migrations, readiness/drain, secret rotation and rollback/recovery. No live provider, cloud deployment, durable storage or independent learner implementation is inferred from the supplied component lessons.
