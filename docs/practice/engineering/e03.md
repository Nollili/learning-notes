# E03 — Security and API boundaries

**Learner status: outstanding.** Reuses P-330/P-331.

## Prerequisites

HTTP, runtime validation and server-established identity. Follow [the reading guide](../../engineering/security.md).

## Scope

Implement one two-user protected read/write using the existing Node/Next contract. Choose cookie/CSRF or a separately designed token flow.

## Observable acceptance

Foreign owner denied at the operation, stale version cannot overwrite, unsafe fields reject, safe errors/logs contain no private sentinel, storage/caches respect scope.

## Failure cases

Anonymous/revoked/foreign actor, forged owner, malformed/oversize body, cross-origin mutation, uncertain write and private cache collision.

## Evidence

Safe HTTP/DB negative checks and threat→control→test map. Browser TLS/cookie/CSP/provider checks need actual declared environments. Retain source/tool versions, expected versus actual, failure→fix→retest and open verification gaps. Author checks never complete this increment.
